# media-flexibility — раздельные дорожки, multi-quality, офлайн

## Report

## [S1] Problem

Жёсткая связка «один торрент = один файл на весь тайтл» не закрывает сценарии:

1. **Раздельные озвучки / видеоряд.** Часто аудио лежит отдельным файлом или
   отдельным торрентом (видео без звука + дорожки). Нужно скачивать
   **конкретные компоненты** разными заданиями и уметь воспроизводить их
   вместе (или перемуксить).
2. **Multi-audio MKV.** В контейнере несколько озвучек — плеер должен
   переключать дорожки.
3. **Watch-party при разном инете.** Хост скачивает два видеоряда
   (низкое + высокое качество) и одну общую озвучку; партнёры получают
   свой вариант.
4. **Оффлайн без квоты.** Скачать серии на устройство локально, не занимая
   квоту S3.

## [S2] Design

### 2.1 Модель компонентов медиа

У `MediaItem` (фильм/эпизод) может быть несколько **составляющих**:

| Роль (`role`) | Что это |
|---------------|---------|
| `video` | основной видеоряд (одна реализация = одна quality) |
| `video_alt` | альтернативное качество того же содержимого |
| `audio` | основная озвучка |
| `audio_alt` | альтернативная озвучка (дубляж / многоголосый / оригинал) |
| `subtitle` | субтитры (может приходить из Bazarr) |

**Источники:**
- **Multi-audio MKV** — один торрент, один файл, несколько audio tracks внутри.
  Задача одна, роль файла `video` (+ metadata о дорожках).
- **Раздельные файлы** — разные торренты: задание `video` + задание `audio`
  (и т.д.), которые потом воспроизводятся как `--audio-file` / remux.

### 2.2 Задачи воркеров (расширение протокола)

Сейчас: `task` привязан к `torrent_release_id`, воркер качает magnet и
заливает файлы в S3.

**Топология:** воркеры — отдельные UNIT'ы на других машинах, без доступа
к root folders *arr и диску сервера. На машине воркера крутится
qBittorrent; *arr может слать загрузки в него через Web API.

Новое:
- У `task_files` появляется `role` (`video` | `audio` | `subtitle` | …) и
  `variant` (строка quality / voiceover label, напр. `1080p`, `dub`).
- Создание **двух заданий** на один `media_item`: `video` (релиз A) и
  `audio` (релиз B). Связь — через `media_item_id` + `role`, не через
  общий torrent.
- Задача остаётся «один торрент → файлы → S3»; **сборка** (remux) — опциональный
  этап:
  - **без remux**: клиент отдаёт в плеер video + выбранный audio-файл
    (mpv `--audio-file`), либо переключает embedded-дорожки;
  - **с remux**: отдельный stage/job, который склеивает video+audio в один MKV
    (ffmpeg) и кладёт как `video` с мульти-дорожками.
- Источник файла на воркере: (1) его локальный qBittorrent (grab из *arr
  или claim magnet), (2) не «чужой» `/data` сервера.

### 2.3 Хранение и каталог файлов

- S3-ключи: `users/{user_id}/{media_item_id}/{role}/{variant}/{filename}`
  или текущий `users/{user_id}/{media_item_id}/{filename}` + metadata
  `role`/`variant` в `task_files`.
- API отдаёт список файлов тайтла с ролями/вариантами, чтобы клиент знал,
  какие сочетания доступны (video 1080p + audio dub + audio eng).
- Доступные **связки** («смотрю 1080p с дубляжом») — policy на клиенте:
  video + предпочитаемый audio (по языку/label); если аудио только
  embedded — используем его.

### 2.4 Multi-quality watch-party

- Комната синхронизирует **таймлайн** (позиция/пауза/скорость), а не байты.
- У сессии есть набор вариантов: `variants = [{quality: "720p", video_file_id}, {quality: "1080p", ...}]`
  + `audio_file_id` (общий).
- Каждый клиент стримит свой вариант (выбор: вручную хостом / авто по
  оценке канала).
- Хост может **заранее скачать** два видеоряда и одну озвучку (см. 2.2)
  до старта сессии — сценарий «слабый инет у партнёра».
- Конфликт качества на seek: перемотка в секундах одинакова; буферы разные.

### 2.5 Оффлайн без квоты

- Скачивание на устройство: `storage=local` (не S3). Квота
  (`DEFAULT_QUOTA_BYTES`) учитывает **только S3** (`storage=s3`).
- Клиент запрашивает URL/файлы компонентов и пишет на диск; JWT обязателен.
- В каталоге офлайн-копии помечаются (`offline: true`), могут жить без
  сети; ревалидация токена при возврате онлайн (полный DRM — вне скоупа).
- Оффлайн можно качать и «неполный» набор (только video 480p + audio) —
  роль/вариант из 2.1–2.2.

### 2.6 Взаимодействие с *arr (Bazarr / Sonarr / Radarr)

- *arr остаётся источником **каталога и автоматизации загрузок**
  (один «основной» файл на эпизод/фильм + субтитры через Bazarr).
- Раздельные audio/alt-quality — **не** обязанность *arr (они обычно
  держат один файл); их добирает seans-воркер по релизам JacRed
  (существующий `/api/media/{id}/releases`).
- Quality/Language profiles в *arr — чтобы «основной» файл был разумного
  качества; multi-audio MKV из релиза заходит как `video` с вложенными
  дорожками.
- Bazarr: субтитры; в seans — роль `subtitle` (позже).

### 2.7 Сценарии (acceptance-level)

| Сценарий | Ожидание |
|----------|----------|
| MKV с 2 озвучками | Плеер переключает audio tracks |
| Video 1080p + отдельный audio dub | Два задания; клиент играет с `--audio-file` или remux |
| Watch-party 720p+1080p+общий audio | Оба клиента синхронны по timeline, у каждого своё качество |
| Оффлайн-скачивание серии | Файл на устройстве, квота S3 не выросла |

## [S3] Out of Scope

- Реализация remux-pipeline (ffmpeg job) в этой фиче — заложить контракт
- Авто-подбор «лучшей» озвучки ML-эмбеддингами
- DRM / оффлайн-лицензии с TTL и отказом воспроизведения
- Транскодинг (HLS, битрейт-лестницы) — только готовые файлы из торрентов
- Изменение Sonarr/Radarr так, чтобы они сами качали отдельный audio
